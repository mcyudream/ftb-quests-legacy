# 中文输入与拼音搜索（modern.20 / Library modern.8）

## 输入中文

点击标题、搜索或正文输入框，在游戏原界面中切换系统中文输入法并输入文字。现代版接收字符事件，而不要求每个字符都对应物理键码。**独立系统编辑窗口、“中”按钮和 F4 弹窗入口已经移除。** 系统输入法自带的候选词界面由操作系统提供，不是另开一个任务编辑器。

正文支持多行、选择、Ctrl+Z／Y 撤销／重做；只有保存后才发送服务端。输入框保持原有字符、字数与有效性校验；补充汉字的 UTF-16 代理对合并为一个完整字符后才插入，避免撤销时留下半个字符。

这一版本沿用 Cleanroom／GLFW 的操作系统字符输入通路，没有另带输入法或词库，也不会在不支持系统输入法的环境强行打开外部编辑窗口。真实游戏字符队列与界面／保存可自动验证，**未把注入字符队列等同于操作系统输入法引擎真实候选词按键测试**。Windows 的实际整合包输入法差异仍需要实际使用反馈。

## 物品选择

| 输入 | 示例目标 |
| --- | --- |
| `铁锭` | 铁锭 |
| `tieding` / `tie ding` | 铁锭 |
| `td` | 含对应连续拼音首字母的物品，如铁锭 |
| `iron_ingot` / `minecraft:iron_ingot` | 注册名匹配 |
| `@minecraft` | 模组命名空间过滤 |
| `lvbaoshi` / `lübǎoshí` / `lubaoshi` | 绿宝石 |

继续匹配玩家当前语言的显示名称、英文／注册名。名称含中文时增加无声调全拼、紧连全拼和连续首字母；支持空格分词、拼音撇号、大小写、全角拉丁字母及 ü／v／u: 写法。搜索只选择原物品栈，不重建／改写注册名、meta 或 NBT。

## 思索选择

同样匹配入口物品名、教程／场景标题和精确教程 ID。例如“能源核心结构搭建”可用 `nengyuanhexinjiegoudajian` 或 `nyhxjgdj` 查找。选中后仍返回 `mod:item#pack:scene` 原始 ID，不将中文或拼音写成链接目标。

Ponder 继续是可选独立前置；未安装时使用原有缺失提示。本轮没有改动 Ponder 运行库。

## 性能与边界

使用正式 Cleanroom 0.4.0 自带的 ICU Han-Latin 转写，未添加下载、联网查询或新的运行库。物品名称及变体仍在客户端线程按批读取；拼音转换在后台增量准备。每个物品持有自己的检索键，即使超过共享缓存的 32768 个名称上限，查询也只做字符串匹配，不重新转写。中文名称和注册名在拼音准备完成前即可搜索；拼音键准备时会自动更新当前结果，首次启动的大索引仍需要后台准备时间。思索也从元数据在后台建索引。

连续输入立即取消旧查询，后台结果只允许更新对应的当前关键词及物品／背包模式。准备新结果期间保留已显示列表，避免每个字符先清空。物品显示名称、注册信息及背包快照在客户端线程读取，搜索线程只处理已捕获的元数据。资源／语言重载会丢弃旧索引并重新准备。

中文多音字采用 ICU 的转写结果，不能保证每个人名、方言读法和自定义词都拥有全部读音别名。拼音依据当前显示名称；英语界面中的纯英文物品名不凭空补充另一套中文语言包名称。

## 安装与验证

客户端和服务端同时替换：

- `FTBQuests-1202.10.0-modern.20.jar`
- `FTB-Library-NovaEng-5.5.4-modern.8.jar`

其他依赖沿用上一包。任务 ID、团队整数 UID、进度、领奖及存储格式不变。

正式 CR 0.4.0 的客户端通过实际游戏键盘字符队列向原物品搜索、标题和多行正文提交中文，检查 F4／原按钮位置不打开额外窗口，并验证补充汉字撤销、拼音筛选、精确思索目标以及中文保存重读。系统输入法真实候选词按键流程及完整 Windows/macOS 整合包未自动实测。此前 modern.16 的 AWT 弹窗报告作为历史证据保留，不能代替本版原输入框验收。

实现参考：[GLFW 文本字符输入](https://www.glfw.org/docs/3.4/input_guide.html#input_char)、[ICU 转写](https://unicode-org.github.io/icu/userguide/transforms/general/)。
